# Deribit Monitor

Тестовое задание на позицию backend python developer. Проект собирает данные с биржи Deribit, сохраняет их в реляционную
базу данных и предоставляет REST API для доступа к исторической и актуальной информации.

Файл задания: [task.md](TASK.md)

## Стек

- fastAPI (Python 3.12+) — API;
- celery + redis — фоновый сбор данных;
- postgreSQL + yoyo migrations — БД и накатка схемы;
- aiohttp — запросы к API Deribit;
- docker compose — контейнеризация;
- pytest - тестирование, ruff - формат и проверка, mypy - статическая типизация, pre-commit - автоматизация проверок;
  перед коммитами.

## Архитектура и проектные решения

1. Решение разбито на 2 блока:
    - src/api - реализация REST API;
    - src/tasks - сборщик данных с биржи.
2. REST API:
    - асинхронный, доступ к БД асинхронный (asyncpg);
    - разбит на слои: роутеры, сервисы, репозиторий. Зависимости инжектируются;
    - реализованы эндпоинты для проверки состояния сервиса и интерактивная документация API;
    - для ендпоинта latest используется кеширование (redis.asyncio);
    - для подключения к БД используется пул соединений;
    - для миграций используется `yoyo`. В основном потому что в проект не тащил SQLAlchemy.
3. Celery:
    - запросы к API Deribit асинхронные, параллельные;
    - запись в базу синхронная (psycopg2). Так как сам по себе Celery синхронный фреймворк, то ни проигрыша ни выигрыша
      не будет.

Ограничения:

- сбор происходит с апи для тестов: https://test.deribit.com/api/v2
- кеш последних цен реализован через Redis; при недоступности Redis API может работать без кеша, но запросы к последним ценам будут обращаться к БД;
- при успешной записи новых цен сборщиком Celery кеш соответствующих тикеров инвалидируется. Если Redis недоступен, API продолжает работать без кеша, а актуальность данных зависит от TTL кеша.

## Быстрый запуск с Docker Compose

Проект полностью контейнеризирован. В [`docker-compose.yaml`](docker-compose.yml) определено 6 контейнеров: postgres,
redis, celery, celery-beat, fastapi и контейнер для подготовки окружения (создания БД и накатки миграций). Rest API
доступен на 8000 порту, остальные контейнеры не доступны (в compose файле есть заглушки для проверки).

### Локальный запуск

Порядок действий:

- склонируйте репозиторий;
- перейдите в корневую директорию проекта;
- подготовьте `.env` файл (можно взять из [примера](env.sample.txt));
- запустите контейнеры через `docker-compose`.

```bash
git clone git@github.com:mkhaykin/deribit_fastapi.git
cd deribit_fastapi
cp env.sample.txt .env
docker-compose up -d
```

Доступ к API по ссылке [http://localhost:8000](http://localhost:8000)

## Использование API и примеры запросов

После успешного старта по адресу http://localhost:8000/ доступно описание системы и примеры типовых запросов,
интерактивная документация (Swagger UI) доступна по адресу: http://localhost:8000/docs

Все методы используют HTTP-метод `GET` и требуют обязательный query-параметр `ticker` (`btc_usd` или `eth_usd`).

### Получение последней сохраненной цены

Возвращает самую свежую запись по указанному тикеру.

Запрос: `GET /api/v1/prices/latest?ticker=btc_usd`

Ответ (JSON):

```json
{
  "id": 516,
  "ticker": "btc_usd",
  "price": "81678.13000000",
  "timestamp": 1792672422
}
```

Важно, цена возвращается как строка, фактически хранится в `Decimal`, в базе как `NUMERIC(24, 8)`. Точность может быть
излишней ...

### Получение всех исторических данных

Возвращает страницу исторических цен для указанного тикера в порядке от новых записей к старым.

Запрос: `GET /api/v1/prices/all?ticker=eth_usd&limit=100`

Параметр `limit` задаёт максимальное количество записей на странице. Для получения следующей страницы используйте
значение курсора из заголовка ответа `X-Next-Cursor`, передав его в следующем запросе.

### Получение цен с фильтрацией по дате

Возвращает цены для указанного тикера за выбранный день.

Запрос: `GET /api/v1/filter?ticker=btc_usd&date=2026-10-22`

Количество возвращаемых записей ограничено параметром `limit`. Для получения полного набора данных за день учитывайте
это ограничение.
